二、当前项目概况

1. 产品定位

ImageX 基于 CPA Image 二次开发，是一个本地优先的 OpenAI 兼容图像生成与编辑控制台。它不提供请求中转后端，用户填写的 API 地址、Key 和模型由浏览器直接使用。

2. 首页模式

- 文生图：调用兼容服务的图片生成接口。
- 图生图：支持本地选择、拖入、粘贴和复用历史图片，调用图片编辑接口。
- 工作流：用于同一产品快速生成主图、白底图、详情图、尺寸图、细节图、场景图六类电商套图。
- 三种模式共用请求队列、生成结果列表、取消、重试、下载、JSON 查看和本地缓存。

3. 协议与供应商

- 支持 OpenAI 兼容协议和 Gemini 协议配置。
- 供应商页面内置“灵速”“Auttyt”“MHOO”和 Gemini，也支持新增、删除和备注名称；左侧用协议色条区分协议类型。
- 当前供应商配置右上角提供“恢复默认参数”，只恢复该供应商字段，不删除任务、图片和提示词；“完全清除”仍是全局清理。
- Gemini 文生图使用浏览器直连 `generateContent`，从 `inlineData`/`inline_data` 提取 Base64 图片；Gemini 图生图暂时明确提示不支持。
- 每个供应商可配置 API URL、Key、模型和协议参数；供应商设置保存在当前浏览器。
- OpenAI 供应商增加图片返回方式（自动兼容、Base64、图片 URL）和多图字段策略（自动优先 `image[]`、重复 `image`、`image[]`）。自动模式遇到明确的参数不支持错误时会重试兼容写法；这些能力会随任务入队冻结，不受之后切换供应商影响。
- 连接测试、错误提示和“说明”面板已改为面向零基础用户的大白话。
- 说明面板只保留“快速上手”和“常见报错”，补充 405、408、413、415、422、5xx、CORS、SSL、无图片响应、临时图片 URL 和浏览器存储不足等解释。
- 生成结果顶部第一行显示当前供应商、协议和可用性标签；第二行显示并发、间隔、延迟。可用性按连通性和延迟分为可用、较慢、不可用或待检测。
- 纯前端架构无法绕过 CORS，也无法真正隐藏 API Key；公网多用户场景应另行设计 BFF/后端。

4. 工作流与产品批次

- 一个工作流任务包含商品信息、产品实拍参考图、可选商业标识/星星素材和六个固定槽位。
- 工作流任务列表改为配置区上方的紧凑横向任务栏，保留快速切换并释放左侧固定栏占用的配置宽度；编辑区开头明确显示当前任务名称和批次。
- 产品实拍图支持多角度多张上传，商业标识/星星素材也支持多张；两类素材均支持本地选择、拖入和从剪贴板粘贴，旧任务的单图字段会自动兼容。
- 单次图生图请求最多使用 5 张参考图；超过上限时会在提交前提示用户减少素材，避免静默丢图。
- 每个槽位支持提示词模板、启用/停用、最终提示词预览、单槽位重试、失败重试、版本记录、最终版本选择和套图导出。
- 每次提交槽位都会记录产品任务 ID、产品批次 ID、批次编号、槽位 key 和版本号。
- 同一产品批次内重新生成会继续递增：v1、v2、v3……；不会因为重新打开任务或切换模式而从 v1 开始。
- 上传产品实拍图后会计算本地 SHA-256 指纹。已有该任务请求且检测到不同图片时，会提示：继续当前批次、开始新产品批次、取消更换。
- 继续当前批次：替换参考图，但保留当前批次的版本记录，后续版本继续递增。
- 开始新产品批次：批次编号加一、生成新的批次 ID、清空槽位最终版本选择；旧批次请求和结果仍保留在生成结果列表中，新批次从 v1 开始。
- 工作流槽位和套图导出只显示当前产品批次，避免不同产品的版本混淆；结果列表通过“批次 N · 槽位 · vN”显示关联。
- 清空槽位版本记录会二次确认，并同时清除右侧结果列表中当前任务、当前批次、当前槽位的请求记录；其他批次不受影响。

5. 标注重生

- 已完成图片可进入“做标记来重新生图”工作区。
- 支持画笔、箭头、矩形、圆形、文字、移动、节点缩放、删除、Ctrl/Cmd+Z 撤销、Ctrl/Cmd+Y 或 Ctrl/Cmd+Shift+Z 重做。
- 文字工具支持点击输入、Enter 提交、单击已有文字再次编辑，并可单独调整文字字号；字号会写入最终导出的标注图。
- 标注画布会在原图四周扩展白色留白：原图内圈选目标区域，箭头指向图外文字说明，减少文字覆盖主体导致模型漏读的问题。
- 提交后在浏览器中合成“白色外扩画布 + 原图 + 标注”的图片并填入图生图图片区域，原图不被覆盖。
- 标注 JSON 持久化、独立补充说明、mask 预览、移动端触控细化和端到端测试仍是后续工作。

6. 开发模式

- 开发模式仅在本地开发构建可用，生产构建会隐藏该能力。
- 已提供普通生成、编辑、失败和工作流六槽位的占位结果，便于不消耗真实 API 额度测试界面。
- 工作流开发示例包含成功、失败、v1/v2 及大量版本记录，用于检查滚动和布局。

三、图片缩略图失效问题

已修复一个确定的本地问题：输入图片使用 blob URL 时，旧逻辑会在请求完成或清理请求时过早 revoke URL，导致输入区仍引用的缩略图裂开。现在只有在输入区和其他排队/运行请求都不再引用该 URL 时才释放。

仍需理解的限制：如果供应商只返回临时远程图片 URL，并且禁止浏览器跨域下载，ImageX 无法保证链接过期后仍可显示。现在会提示“预览可能正常，导出或再次编辑可能受限”，但不能从纯前端绕过 CORS。服务端应提供可长期访问的图片 URL 或正确 CORS；不能永久禁止 revoke，否则会造成浏览器内存泄漏。

五、下一步建议

阶段 1：本机人工验收

1. 在工作流中创建任务，上传产品图，生成一槽位后再次生成，确认版本为 v2。
2. 更换另一张产品图，分别测试“继续当前批次”和“开始新产品批次”；确认旧结果仍在列表，新批次从 v1 开始。
3. 清空当前槽位版本，确认只清除当前批次对应结果，不影响其他批次。
4. 在文生图、图生图、工作流之间切换，等待请求完成后再检查产品图、商业素材和图生图缩略图。
5. 测试刷新浏览器、移动端宽度、远程图片 URL、单图下载和 ZIP 导出。

阶段 2：可靠性和架构

1. 增加批次切换和 blob URL 生命周期的更多组件测试，补充真实浏览器 Playwright 冒烟测试。
2. 将 API provider adapter、请求执行、队列调度、结果缓存从 use-image-console.ts 中逐步拆分。
3. 增加 AUTTYT 等真实供应商的同步兼容验收：最小文生图、单图编辑、多图 `image[]`、重复 `image`、URL 返回和 CORS 下载。
4. 评估供应商异步图片任务：提交 `task_id`、轮询状态、刷新后恢复；默认仍保留同步模式，不在没有真实需求前强制启用。
5. 增加 IndexedDB schema 版本迁移、损坏恢复、容量提示和本地备份恢复。
6. 统一错误分类：CORS、鉴权、参数、限流、服务端错误、响应格式错误，并在“说明”中用大白话解释。
7. 评估大图和大批量 ZIP 的内存占用，必要时改为分批读取和导出。

阶段 3：电商套图增强

1. 支持套图模板复制、导入导出和平台预设，但不要把平台规则硬编码成不可修改的提示词。
2. 增加商品字段变量和槽位提示词模板管理，继续保持用户可编辑。
3. 增加批次对比、槽位进度总览和更清晰的旧批次/新批次筛选。
4. 在确认真实需求后再考虑多产品批处理、mask 局部编辑、云同步或团队协作。

接手时不要做的事情：
- 不要删除或回退现有未提交改动。
- 不要自动同步 Git，除非用户明确说“同步 Git”。
- 不要把 API Key、完整响应、真实图片或本地路径写进导出 JSON、日志、测试 fixture 或 README。
- 不要把纯浏览器项目改成默认上传用户数据的服务端架构。

六、下一次优先事项（本轮暂缓）

本轮曾开始实现以下供应商兼容能力，但因方案尚未完整验证，相关半成品代码已全部撤回，不进入本次生产包：

1. 自定义认证方式：允许供应商配置 API Key Header 名称及 Key 前缀，例如 `Authorization: Bearer ...` 或 `x-api-key: ...`。
2. 异步任务轮询：支持提交后取得 `task_id`，按可配置 URL 模板轮询任务状态，并从可配置结果路径提取图片。
3. 通用请求/响应字段映射：兼容非标准供应商的任务 ID、状态、错误和图片结果字段，避免为每家供应商硬编码分支。
4. 配置页与主页连接测试优化：保存后的测试状态、超时/取消、错误分类和结果展示保持一致，并减少重复请求。
5. API 余额展示：仅在供应商提供标准且允许浏览器跨域访问的余额接口时启用；无法可靠检测时不显示误导数据。

实施原则：先设计独立的 provider adapter/协议适配层，明确同步响应、异步响应、鉴权和字段映射的数据结构；再补齐自定义 Header、空前缀、轮询中/成功/失败/超时/取消、嵌套结果路径等单元测试和真实供应商验收。全部验证通过后再接入设置 UI，避免半成品进入生产环境。
