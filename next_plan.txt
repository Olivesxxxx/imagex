二、项目概况

1. 产品定位

ImageX 基于 CPA Image，是一个本地优先的 OpenAI 兼容图像生成与编辑控制台。它是纯浏览器前端，不包含业务后端，也不在项目服务器保存用户数据。浏览器直接请求用户配置的 OpenAI 或兼容 API。

2. 当前主要能力

- 文生图：调用 /v1/images/generations。
- 图片编辑：调用 /v1/images/edits，支持本地选择、粘贴图片和复用历史结果，最多 5 张输入图。
- 图片输入：图生图图片区域支持粘贴和从本地文件系统拖放，拖放仅接收图片文件。
- 私有协议生图：使用 x-api-key，调用 /api/images/generations 与 /api/images/edits；当前只支持同步文生图和图生图，不接入视频或异步任务接口。
- Responses 生图：调用 /v1/responses，并使用 image_generation 工具。
- Chat Completions 生图：调用 /v1/chat/completions，并使用 image_generation 工具。
- 连接测试：调用 /v1/models。
- 批量与队列：单次最多创建 100 个请求；并发度 1-100；请求间隔 0-3600 秒；支持取消、过滤和清理。
- 结果处理：兼容 URL/base64 图片结果，支持单图下载、历史结果再次编辑、响应 JSON 查看和完成图片 ZIP 导出。
- 标注重生第一版：已完成结果图进入“做标记来重新生图”工作区，支持选择/移动、画笔、箭头、矩形、圆形、文字、撤销/重做、删除/清空和浏览器内合成导出。
- 配置与预览：配置面板已按 OpenAI 协议/私有协议分区；支持重置参数和二次确认的本机数据完全清除；主结果图片支持单击查看大图与多图切换。
- 本地工作流：保存设置、生成/编辑各自的 Prompt 草稿与历史、Prompt 置顶、请求摘要和请求详情。
- 国际化：中文和英文，语言状态体现在 URL 路径。
- SEO/静态部署：Vite 构建后执行预渲染，仓库包含 robots、sitemap、manifest、Netlify headers/redirects 和 SEO CI 检查。

3. 技术栈

- React 19 + TypeScript 6
- Vite 8
- Tailwind CSS 4
- shadcn/ui 风格组件，底层使用 Radix UI
- Vitest + Testing Library + jsdom
- lucide-react 图标，sonner 消息提示
- 无服务端数据库、无鉴权服务、无环境变量依赖

4. 核心代码结构

- src/App.tsx：三栏主界面及各类确认/进度/JSON 对话框的组合入口。
- src/hooks/use-image-console.ts：核心运行状态；负责队列调度、请求执行、取消、结果缓存、下载和界面动作。目前约 68 KB，是后续维护风险最高的单体模块。
- src/lib/image-console.ts：领域类型、默认设置、参数校验、四类请求载荷、响应解析、缓存模型和格式化工具。目前约 58 KB。
- src/lib/api.ts：HTTP 请求、Bearer 鉴权、JSON/文本响应解析和错误转换。
- src/lib/endpoints.ts：从用户填写的 Base URL 规范化五类直连端点。
- src/lib/storage.ts：localStorage 与 IndexedDB 持久化、迁移和清理。
- src/lib/request-queue.ts：并发数、请求间隔和下一任务调度规则。
- src/components：生成参数、请求列表、结果区、设置窗口和基础 UI 组件。
- src/lib/*.test.ts、src/App.test.tsx：领域逻辑、存储、队列、端点、结果和主要交互测试。

5. 数据与安全边界

- localStorage 保存设置、Prompt 草稿和 Prompt 历史。
- IndexedDB 数据库名为 ImageX，保存请求摘要、响应详情和图片缓存。
- API Key 默认只保存在当前运行内存；只有用户启用“记住 API Key”后才写入 localStorage，存储时没有加密。
- ImageX 不提供请求中转代理，目标 API 必须正确配置 CORS。
- 纯前端架构意味着浏览器 CORS 是硬约束，也无法真正隐藏 API Key。若未来面向多用户或公网部署，应新增自有后端/BFF，而不是继续把密钥放在浏览器。

6. 当前已知问题与技术风险

- npm audit 报告 2 个 high：vite 间接依赖 postcss@8.5.15，jsdom 间接依赖 undici@7.27.2；均显示 fixAvailable=true。它们主要位于开发/测试工具链，但仍需升级和回归。
- use-image-console.ts 和 image-console.ts 体积过大，UI 状态、业务编排、请求适配及缓存逻辑耦合，新增功能时容易扩大回归面。
- 当前可分别配置一套 OpenAI 协议和一套私有协议地址、Key 与模型，但还不支持多个供应商档案、快速切换、模型自动发现或更完整的供应商级参数差异。
- OpenAI 兼容接口实际返回结构差异较大。当前已有多种响应提取兼容逻辑，但缺少明确的 provider adapter 边界和真实服务契约测试。
- 队列仅存在单浏览器实例中；刷新后的 queued/running 请求会如何恢复需作为验收项重点检查，不能视作服务端可靠任务队列。
- ZIP 为项目自行实现的浏览器端打包逻辑，大批量/大图片时可能产生较高内存占用。
- 没有端到端浏览器测试；现有测试以单元和组件测试为主，真实 CORS、下载、IndexedDB、刷新恢复和响应图片加载仍需人工或 Playwright 覆盖。
- Git 远程应只指向 ImageX 自有仓库；上游来源通过 README 与 MIT License 说明。

- 失败请求重试、指数退避、429/5xx 分类处理、仅重跑失败项。
- 图库视图、Prompt/模型/尺寸/日期筛选、收藏和标签。
- 请求参数模板与 Prompt 模板变量。
- 对比视图、批量选择、批量下载/删除/再次编辑。
- 本地数据备份与恢复。
- 可选的自托管 BFF，用于解决 CORS、隐藏上游密钥和实现团队权限。

每个功能的完成标准：类型检查通过、相关单元测试通过、关键路径端到端测试通过、生产构建通过、真实兼容 API 冒烟通过、API Key 未泄露。

阶段 5：做标记来重新生图（下一阶段核心功能）

目标：在当前生成图片上直接标记不满意或缺失的区域，并将图片与标记说明作为一次新的图生图请求输入。该功能仍保持纯浏览器前端，原图、标记和请求数据只保存在当前浏览器。

当前进度：第一版交互已接入。结果图片右上角可打开标注工作区；提交后会生成新的本地标注图并自动填入图生图专属图片区域，原始图片保持不变。标注工作区支持 Ctrl/Cmd+Z 撤销、Ctrl/Cmd+Y 或 Ctrl/Cmd+Shift+Z 重做，以及 Delete/Backspace 删除选中标记；文字工具可在画布点击位置直接输入，单击已有文字可再次编辑，输入框与选中轮廓会按实际文字宽度适配；箭头支持拖动两个端点缩放，矩形和圆形支持拖动四角节点缩放；任意绘图工具状态下均可直接拖动已有标注。剩余工作重点是标注 JSON 的本地持久化、独立的补充说明记录、移动端触控细化、mask 预览和端到端测试。

1. 入口与交互
   - 在当前生成图片右上角操作区增加“做标记来重新生图”按钮，使用编辑/标注语义的图标。
   - 点击后打开标注工作区；原有“作为参考图”和旋转按钮继续保留，功能不互相覆盖。
   - 标注完成后可取消、清空、撤销/重做，并预览最终提交效果。
   - 标注工作区在桌面端和移动端都必须保持图片比例、工具栏可操作和按钮不遮挡画布。

2. 第一版工具范围
   - 画笔：可调笔刷大小，支持橡皮擦或清除局部标记。
   - 箭头：拖拽起点和终点，支持调整粗细。
   - 矩形/圆形：用于圈选问题区域，支持调整边框粗细。
   - 文字：点击画布定位后输入说明，支持移动、删除和基础字号设置。
   - 选择工具：选中、移动、删除已有标注，避免只能按创建顺序修改。

3. 数据与请求设计
   - 原图作为底图，标注层独立存储，避免破坏原始生成图片。
   - 提交前在浏览器中合成带标注的参考图，并保留原图、标注 JSON、合成图之间的关联。
   - 将用户补充说明与原提示词分开显示，提交时生成明确的编辑提示词；不得静默覆盖原提示词。
   - 复用现有图生图队列、取消、失败处理、历史记录和本地缓存，不新增服务端存储。
   - 明确不同 OpenAI 兼容服务对 mask/透明区域/带标记图片的支持差异；第一版优先兼容无需 mask 的“带标记参考图 + 提示词”流程，并为后续 mask 输出保留扩展点。

4. 推荐实现顺序
   - 先抽取独立的 `annotation-canvas` 组件和标注模型，完成画布缩放、坐标换算、撤销/重做。
   - 再实现画笔、箭头、矩形/圆形、文字四类工具及移动端触控事件。
   - 增加合成导出、透明背景/mask 预览和图生图请求适配。
   - 接入历史记录与结果卡片，支持从任意已完成图片再次进入标注工作区。
   - 最后补充大图性能、键盘快捷键、无障碍标签和 Playwright 交互测试。

5. 验收标准
   - 四类标注可以创建、移动、删除，撤销/重做结果稳定。
   - 标注不会改变原始图片；取消编辑不会产生新请求。
   - 提交后生成一条新的图生图任务，原任务与新任务可区分并能复用提示词。
   - 刷新页面后，已保存的标注任务不会丢失或污染其他请求详情。
   - 桌面端/移动端无按钮遮挡、坐标偏移或画布溢出；类型检查、测试、构建和真实兼容 API 冒烟全部通过。

阶段 6：电商产品六图快速生成（重点产品方向）

目标：把同一款产品的主图、白底图、详情图、尺寸图、细节图、场景图，从六次重复的手动生图，变成一次建立产品任务、批量生成六种用途图片。仍保持纯浏览器前端：同一张产品实拍图只在浏览器内复用，六个请求分别直连用户选择的图像 API。

当前进度：产品任务、六槽位模板、生成整套批量入队、请求显式关联、槽位状态、结果回填、槽位级重试、版本选择、槽位结果操作入口以及整套导出均已完成。已有“产品套图”入口和本地产品套图任务工作区，支持创建、编辑、删除产品任务；可上传一张产品实拍参考图和可选商业标识/星星素材；可填写商品名称、材质/颜色、核心卖点、尺寸数据、禁用元素、品牌语气和目标平台。每个任务包含主图、白底图、详情图、尺寸图、细节图、场景图六个固定槽位；每个槽位可启用/停用、编辑提示词模板、恢复默认模板，并预览插入商品信息后的最终提示词。点击“生成整套”会先显示确认弹窗并校验产品参考图与启用槽位，然后将每个启用槽位作为一条独立图生图任务加入现有队列，每槽位固定一张；所有槽位复用产品实拍图，主图可额外携带商业标识素材。每条套图请求会保存产品任务 ID、槽位 key 和版本号，套图工作区据此显示未提交、排队中、生成中、已完成、失败或已取消。最新完成结果会以缩略图回填到槽位，可定位到主结果面板查看大图或导出图片；完成槽位可单独重新生成，失败/取消槽位可单独重试，也可一键仅重试失败槽位，重试时自动递增版本号且不会重复提交其他槽位。槽位显示版本历史，用户可切换已完成版本并将任意版本设为最终版本，选择结果保存到 IndexedDB，刷新后仍可恢复。每个完成版本现在都可以直接作为图生图参考图，或打开“做标记来重新生图”工作区；标注入口会优先读取原图详情。产品套图弹窗在桌面端最大约 1440px，宽屏槽位采用两列，小屏自动单列。现在可以按产品名导出整套 ZIP，包含选定版本图片和脱敏 `产品套图参数.json`，不包含 API Key、完整响应或本地路径。任务、槽位模板与图片保存在当前浏览器 IndexedDB，生图请求仍由浏览器直连用户配置的 API，不上传到 ImageX 服务器；“完全清除”会同步清除产品套图任务和参考图。下一步将产品套图改为首页主区域的顶层工作流模式。

一、建议的用户流程

1. 创建“产品套图任务”，上传一张产品实拍图；可选上传商业标识/星星素材、品牌 Logo、字体或其他固定素材。
2. 填写一次商品基础信息：商品名称、材质/颜色、核心卖点、尺寸数据、禁用元素、品牌语气和目标平台。
3. 选择一个“六图模板”，系统预置六个成图槽位：主图、白底图、详情图、尺寸图、细节图、场景图。
4. 每个槽位显示可编辑的提示词模板和必要参数；商品基础信息作为变量自动插入，产品实拍图自动作为同一参考图。
5. 点击“生成整套”，由现有队列创建六个图生图请求；支持并发数、间隔、取消、失败重试和仅重跑失败项。
6. 六张图生成后以套图方式查看，可单张重新生成、替换提示词、作为参考图、做标记来重新生图或导出整套 ZIP。

二、六个默认模板的职责

- 主图：突出产品主体、商业识别和第一眼卖点；允许额外叠加星星/商业标识素材。
- 白底图：纯白或平台要求的干净背景，产品轮廓、颜色和比例准确，避免额外道具。
- 详情图：用一到三个局部构图解释材质、结构、功能或核心卖点，文字说明可后续由 ImageX 叠加而不是完全依赖模型生成。
- 尺寸图：根据用户填写的长宽高、重量或容量生成带尺寸标注的展示图；尺寸数据必须作为结构化字段保存，并在提示词中明确禁止篡改。
- 细节图：放大纹理、接口、缝线、按钮、包装或其他需要检验的细节，保持与产品实拍图一致。
- 场景图：把产品放入指定生活/使用场景，提供场景风格、光线、镜头和目标人群，避免改变产品本体。

三、建议优先加入的功能

1. 套图模板管理：内置默认模板，支持复制、编辑、启用/停用和导入导出 JSON。
2. 变量系统：例如 `{{商品名}}`、`{{材质}}`、`{{颜色}}`、`{{尺寸}}`、`{{核心卖点}}`、`{{场景}}`；提交前预览最终提示词。
3. 统一产品参考图：上传一次，六个请求自动复用；请求记录保存引用关系，避免重复选择。
4. 一致性约束：提供可选的“产品一致性要求”字段，由用户自行填写；为空时不自动追加任何固定一致性指令。
5. 槽位状态看板：六个槽位分别显示排队中、生成中、完成、失败、已跳过；支持单槽位重试。
6. 预览与版本：每个槽位保留最近版本，可在最终导出前选择版本；原图和生成图不互相覆盖。
7. 平台预设：淘宝/天猫、京东、拼多多、独立站等预设尺寸、背景和文案安全区，但不把平台规则硬编码到提示词里。
8. 套图导出：按“产品名/主图.png、白底图.png……”命名，导出 PNG/JPEG 和一份 JSON 参数清单；API Key、完整响应和本地路径不得进入导出文件。

四、推荐的第一期范围

- 先实现一个产品套图工作区，不做复杂的账号、云同步或在线协作。
- 先支持一张产品参考图 + 六个固定槽位 + 可编辑提示词模板 + 批量提交 + 单槽位重试 + 套图导出。
- 首版不自动生成平台营销文案，不把六张图拼成一张长图，也不强制模型在图里生成大段文字；尺寸、卖点和说明文字优先由结构化字段和后置叠加工具处理。
- 使用现有图生图队列和 ImageX 标注工具，后续再增加局部 mask、参考图权重和多产品批处理。

五、验收标准

- 用户只需上传一次产品实拍图，即可提交六个用途明确的图生图请求。
- 六个槽位的最终提示词可预览、可单独修改；产品一致性要求由用户自行填写并可随任务保存。
- 任一槽位失败不会影响其他槽位；可只重试失败槽位并保留已完成版本。
- 刷新浏览器后，套图任务、六个槽位状态、参考图和已生成版本仍能恢复。
- 套图导出命名稳定、图片可打开、参数清单脱敏；类型检查、测试、构建和真实 API 冒烟全部通过。
